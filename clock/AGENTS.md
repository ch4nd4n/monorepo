## Working Rules
1. **Do not start implementation** unless explicitly asked.
2. Prioritize requirement clarity and UX decisions before architecture.
3. Keep decisions documented in markdown under `docs/`.
4. Prefer incremental proposals and explicit trade-offs.
5. Follow `docs/coding-standards.md` for all code and refactors.

## Expected Initial Workflow
1. Run a grilling/discovery session.
2. Refine PRD with validated decisions.
3. Propose frontend architecture options.
4. Wait for implementation approval.

## Documentation Conventions
- Use concise markdown with headings and checklists.
- Keep assumptions clearly labeled.
- Capture open questions separately from confirmed decisions.
